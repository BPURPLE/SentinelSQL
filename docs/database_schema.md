# SentinelSQL Database Schema

**Version:** 1.0 (MVP)  
**Status:** Design Freeze

---

# 1. Purpose

This document defines the relational database schema for SentinelSQL.

The schema stores authentication data, audit records, SQL query metadata, detection results, incidents, and AI-generated explanations.

The database supports only the MVP defined in the Product Specification and Software Architecture.

---

# 2. Database Engine

- PostgreSQL
- UTF-8 Encoding
- ACID Transactions
- Parameterized Queries Only

---

# 3. Design Principles

The database follows these principles:

- Normalized relational design.
- Least-privilege access.
- Immutable security logs.
- No duplicate security data.
- Referential integrity enforced through foreign keys.
- Sensitive data is never stored in plaintext.

# 5. Tables

---

## 5.1 Users

Stores authenticated users.

### Columns

| Column | Type | Constraints |
|---------|------|-------------|
| id | UUID | Primary Key |
| username | VARCHAR(100) | Unique, Not Null |
| email | VARCHAR(255) | Unique, Not Null |
| password_hash | TEXT | Not Null |
| role | VARCHAR(30) | Not Null |
| created_at | TIMESTAMP | Not Null |
| updated_at | TIMESTAMP | Not Null |

---

## 5.2 Queries

Stores metadata for every intercepted SQL query.

### Columns

| Column | Type | Constraints |
|---------|------|-------------|
| id | UUID | Primary Key |
| user_id | UUID | Foreign Key → Users.id |
| query_text | TEXT | Not Null |
| canonical_query | TEXT | Not Null |
| tokens | JSONB | Not Null |
| request_ip | INET | Not Null |
| created_at | TIMESTAMP | Not Null |

Notes

- Stores the canonicalized query used by the detection pipeline.
- Stores extracted SQL tokens.
- Records the originating client IP.

---

## 5.3 Detections

Stores outputs from the detection layer.

### Columns

| Column | Type | Constraints |
|---------|------|-------------|
| id | UUID | Primary Key |
| query_id | UUID | Foreign Key → Queries.id |
| rule_detected | BOOLEAN | Not Null |
| rule_name | VARCHAR(100) | Nullable |
| ml_prediction | VARCHAR(20) | Not Null |
| ml_confidence | DECIMAL(5,4) | Not Null |
| risk_score | INTEGER | Not Null |
| created_at | TIMESTAMP | Not Null |

Notes

- Stores both rule-based and ML results.
- Risk score is generated by the Threat Decision Engine.

---

## 5.4 Incidents

Stores enforcement decisions.

### Columns

| Column | Type | Constraints |
|---------|------|-------------|
| id | UUID | Primary Key |
| detection_id | UUID | Foreign Key → Detections.id |
| action | VARCHAR(20) | Not Null |
| status | VARCHAR(30) | Not Null |
| created_at | TIMESTAMP | Not Null |

Allowed Actions

- ALLOW
- BLOCK

---

## 5.5 AI Explanations

Stores advisory AI explanations.

### Columns

| Column | Type | Constraints |
|---------|------|-------------|
| id | UUID | Primary Key |
| incident_id | UUID | Foreign Key → Incidents.id |
| explanation | TEXT | Not Null |
| validated | BOOLEAN | Not Null |
| created_at | TIMESTAMP | Not Null |

Notes

- AI output is advisory only.
- AI explanations never influence enforcement.

---

## 5.6 Audit Logs

Stores immutable security events.

### Columns

| Column | Type | Constraints |
|---------|------|-------------|
| id | UUID | Primary Key |
| user_id | UUID | Foreign Key → Users.id |
| query_id | UUID | Foreign Key → Queries.id |
| incident_id | UUID | Foreign Key → Incidents.id |
| event_type | VARCHAR(50) | Not Null |
| event_details | JSONB | Not Null |
| created_at | TIMESTAMP | Not Null |

Notes

- Records authentication events.
- Records SQL query processing.
- Records detections.
- Records enforcement actions.
- Records AI explanation generation.

Audit records are append-only.

---

# 7. Security Constraints

- Passwords are stored only as bcrypt hashes.
- SQL execution uses parameterized queries exclusively.
- UUIDs are used as primary keys.
- Foreign keys enforce referential integrity.
- Audit records are immutable.
- No plaintext credentials are stored.

---

# 8. Indexing Strategy

Indexes should be created on:

- Users.username
- Users.email
- Queries.user_id
- Queries.created_at
- Detections.query_id
- Detections.risk_score
- Incidents.action
- AuditLogs.created_at

---

# 10. Schema Constraints

- One Query produces one Detection.
- One Detection produces one Incident.
- One Incident may have one AI Explanation.
- Every security event is audit logged.
- AI explanations are informational only.
- Audit logs are never modified after creation.

---

# 11. Future Extensions

The schema is designed for future expansion without affecting the MVP.

Potential future additions include:

- Multi-tenant support
- Additional database engines
- Threat intelligence tables
- Rule management tables
- Model version tracking
- User session history
- API key management

These extensions are outside the MVP scope.
